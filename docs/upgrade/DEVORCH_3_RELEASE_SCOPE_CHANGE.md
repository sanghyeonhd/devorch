# Devorch 3 — 범위 변경 기록: 단계적 이관에서 릴리스 완주로

**작성일:** 2026-08-19
**선행 문서:** `DEVORCH_3_RUST_MULTI_AGENT_ADE_IMPLEMENTATION.md`, `DEVORCH_3_RUST_AGENT_OPERATING_LAYER_IMPLEMENTATION.md`, `DEVORCH_3_DEVELOPMENT_SIMULATION_VALIDATION.md`
**후속 문서:** `DEVORCH_3_RELEASE.md` — 이 범위가 실제로 착지한 위치. `DEVORCH_3_CHAT_GUI_AND_REUSE.md` — 채팅 우선 GUI와 재사용으로 제품을 끝내는 방법.
**상태:** 이 문서가 위 세 문서의 **웨이브 순서와 속도**를 대체한다. 기술적 판단(무엇을 어떻게 만들 것인가)은 그대로 유지한다.

## 1. 무엇이 바뀌었나

원 계획은 R0부터 R7까지 웨이브마다 게이트를 두고, 네 개의 에이전트가 각자
워크트리에서 티켓 단위로 작업하며 몇 주에 걸쳐 진행하는 형태였다.

변경된 목표는 다음과 같다.

```text
전 코드베이스를 Rust로 완전 전환
+ 네이티브 Rust GUI 데스크탑 앱 완성
+ Go 런타임 완전 제거
+ 라이센스 부여
+ GitHub 릴리스 출시
```

즉 **R3부터 R7까지를 한 번에 완주하고 출시**한다.

## 2. 유지되는 것

원 문서의 기술적 결론은 하나도 버리지 않는다.

- Rust 단일 언어, 네이티브 `egui/eframe` GUI (Tauri 아님)
- 후보 평가 시 `git diff` 단독 사용 금지, 완전한 변경 인벤토리 필수
- 유휴 에이전트 프로세스 0개, `max_parallel_agents` 기본 2
- 구조화된 헤드리스 출력 우선, PTY는 폴백
- 결정론적 프로그램 상태가 에이전트의 주장보다 항상 우선
- 어댑터 교차 배정 원칙 (작성자와 검증자 분리)
- 네이티브 마우스/키보드 제어는 정책·검증 엔진 이후

## 3. 변경되는 것과 그 이유

### 3.1 웨이브 게이트 → 단일 릴리스 게이트

원 계획의 웨이브 게이트는 **네 개의 에이전트가 병렬로 작업할 때** 머지 충돌과
책임 소재를 관리하기 위한 장치였다. 단일 실행 주체가 순차적으로 구현하는
경우 그 비용은 발생하지 않는다. 대신 릴리스 게이트 하나로 대체한다.

```bash
cargo fmt --all -- --check
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo xtask verify-agent-rules
```

### 3.2 Go 퇴역 조건의 재정의

원 문서 §43은 Go 제거 전 "선택된 모든 Go 동작에 대한 parity 테스트"를
요구했다. R0 실측 결과 **97개 패키지 중 테스트 파일은 3개**였다.

parity 테스트의 대상이 되는 "검증된 동작"이 사실상 존재하지 않는다. 없는
기준선에 대한 parity를 작성하는 것은 Go 코드를 Rust로 옮겨 적으면서 그것이
옳다고 스스로 선언하는 일이며, 원 문서 §16이 명시적으로 금지한 "줄 단위 번역"과
같은 결과를 낳는다.

따라서 퇴역 조건을 다음으로 대체한다.

```text
(구) Go 동작마다 parity 테스트
(신) Rust 구현이 자체 테스트로 동작을 증명하고,
     Go 트리는 devorch-go-final 태그로 보존한 뒤 제거
```

Go 데이터베이스(`devorch.db`)는 삭제하지 않는다. Rust는 `devorch3.db`를
사용하며 두 파일은 계속 공존한다. OkAON 이관은 `sql-schema-map.md`의 처분표를
따르되 별도 작업으로 남긴다.

### 3.3 어댑터 검증 방식

교차 배정(작성자 ≠ 검증자)의 목적은 "에이전트가 자기 통합의 유일한 검증자가
되지 않도록" 하는 것이다. 단일 실행 주체에서는 이를 다음으로 대체한다.

```text
녹화된 fixture에 대한 결정론적 테스트  ← 기본 CI
실제 CLI 라이브 스모크                  ← 옵트인 (DEVORCH_LIVE_*=1)
```

fixture는 각 벤더의 실제 이벤트 스키마를 반영하며, 정규화 결과가 동일한
`AgentEvent` 계약으로 수렴하는지 검사한다. 이것이 "네 개의 어댑터가 같은
계약으로 수렴한다"는 Gate R2의 실질이다.

## 4. 범위에서 제외되는 것 (출시 시점 기준)

정직하게 남긴다. 아래는 이번 릴리스에 **없다**.

- 네이티브 마우스/키보드 제어 (Document 2의 `devorch-computer-*`)
- 브라우저 자동화 런타임
- 자율 레벨 5
- OkAON 학습 데이터의 Go → Rust 이관 실행

이유는 원 문서 §53의 순서 자체가 옳기 때문이다. 정책 엔진과 검증 엔진이
릴리스에 포함되므로 다음 릴리스에서 네이티브 제어를 얹을 수 있는 상태가 된다.
지금 얹으면 문서가 "즉시 거부" 대상으로 규정한 패치가 된다.

## 5. 경쟁 제품 대비 목표

Orca 계열 멀티 에이전트 ADE 대비 Devorch의 차별점은 다음 네 가지로 정의한다.

| 항목 | 일반적인 ADE | Devorch 3 |
|---|---|---|
| 후보 평가 | diff 크기 / LLM 판단 | 결정론적 게이트 우선, 완전한 변경 인벤토리 |
| 미채택 파일 | `git diff`만 관찰 | untracked / generated / binary / secret 분류 |
| 에이전트 수 | 설치된 만큼 상시 실행 | 위험도 기반 후보 수, 유휴 프로세스 0 |
| 권한 | 벤더 권한에 위임 | Devorch 정책이 최종 결정, 능력 기반 |

"네 모델을 동시에 돌린다"는 기능이 아니라 자원 낭비라는 것이 원 문서 §4의
결론이며, 이 릴리스는 그 결론을 제품 기본값으로 만든다.

## 6. 이 문서가 유효한 범위

이 문서는 **일정과 절차**만 변경한다. 다음은 여전히 위반 시 패치 거부 사유다.

- 실패하는 명령을 숨기는 것
- 테스트를 지워 게이트를 통과시키는 것
- 관측하지 않은 빌드 성공을 보고하는 것
- 웨이브를 앞질러 네이티브 제어를 구현하는 것
